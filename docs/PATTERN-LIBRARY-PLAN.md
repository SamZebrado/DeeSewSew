# Pattern Library / Guide System 2.0 — bounded first collection

Base: published 1fe2ad324bfb3d2c3732ab1ee91a62a8e145abaa. Independent of3D/audio/petting.

## Audit and decision

GuidePattern already contains versioned identity, desired face strokes and physical runs. Flower adapts a frozen alternating route based on current needle position/side; preserve this adapter and its existing optional session. Tulip guide instead hardcodes two-anchor runs and index24 face boundary. Extract a reusable explicit-run session/action derivation; retain its old storage key/session adapter and exact geometry. Canonical ThreadRun operations remain authoritative, optional guide state never becomes artwork.

## Sequence

1. Add a small typed catalog: title/difficulty/palette/presentation plus either the preserved flower adapter or a GuidePattern definition. Four entries only: existing flower/tulip-heart and proposed simple leaf/cherries. No generated fake curves or hidden connectors.
2. Compile real run boundaries into canonical start/stitch/cut actions; derive face from run definition, not global indices. Camera flip remains an instruction, not a fabricated topology edit. Validate optional restored guide state against catalog version and committed artwork.
3. Keep existing two quick-entry controls for compatibility; add one collapsed “What would you like to stitch?” select/start chooser for the entire collection. New content requires catalog data, not a new button/handler. Free embroidery remains default. UI uses existing soft-button layout/localization contract.
4. Validate new patterns by executing their canonical runs and comparing independent target edge sets. Add progress/cut/mismatch/reload/undo tests. Stop any motif failing visual recognition rather than expand the collection.
5. Inspect actual canonical renderer screenshots and real pointer guide completion for both new motifs; desktop/tablet/phone and both locales. Run existing guide/cut/storage/PNG/layout regressions, full appropriate gates.
6. Only a coherent clean candidate receives an independent exact-SHA High request. No inherited approval; ordinaryFF, Pages and public smoke follow only approval.

No normal artwork schema, physics, topology, renderer or existing motif changes. No timing/replayability claims inferred from machine speed; human1–3 minute goal remains a qualitative design target until measured.
